# 智能体私密/公开发布功能实现计划

## 目标
用户创建的智能体默认私密（仅自己可见可聊）；开启「发布」后进入「智能体广场」，所有注册用户可聊天。共享聊天使用发布者配置的 API Key（成本归发布者），共享者可检索发布者的知识库。

## 后端改造

### 1. 数据模型与迁移
- `app/models/user_agent.py`：新增 `is_published = fields.BooleanField(default=False, description="发布到广场")`。
- `app/core/init_app.py`：仿照 `ensure_user_agent_supports_vision_column()` 新增 `ensure_user_agent_is_published_column()`（`ALTER TABLE "user_agent" ADD COLUMN "is_published" INT NOT NULL DEFAULT 0`，捕获 duplicate column），并在 `init_db()` 中调用。不新增 aerich 迁移文件（沿用 supports_vision 的兜底惯例）。
- 无需改聊天库（Postgres）：会话已按 (user_id, agent_id, session_id) 隔离。

### 2. Schema（`app/schemas/user_agent.py`）
- `UserAgentCommon` 增加 `is_published: bool = False`，创建/更新接口自动可用。

### 3. 访问控制（`app/controllers/user_agent.py`）
- 新增 `get_accessible(agent_id, user_id)`：`filter(id=agent_id).filter(Q(user_id=user_id) | Q(is_published=True))`。
- 保留 `get_owned()` 用于属主专属的写操作（更新/删除/头像/知识库管理）。

### 4. 智能体 API（`app/api/v1/user_agents/user_agents.py`）
- `GET /get` 改用 `get_accessible`；非属主时隐藏 `has_api_key` 与 `api_key` 相关字段。
- 新增 `GET /public`（tags="智能体模块"，分页）：`is_published=True` 列表，`select_related("user")` 取发布者 username，返回含 `owner_username`/头像 URL（用发布者 username 生成，`_public_agent_dict` 的 username 参数统一改为属主）。
- `/update`：当 `is_published` 置真但 `api_key_ciphertext` 为空时返回 Fail，提示先配置 API Key。
- `/list` `/create` `/update` `/delete` `/upload_avatar` 维持 `get_owned`。
- 权限说明：新路由自动被 `init_apis()`/`ensure_user_agent_apis_for_roles()` 同步授权，无需手工配角色。

### 5. 聊天链路（`app/api/v1/user_agents/chat.py`）
- 9 处 `get_owned` 校验全部改为 `get_accessible`（附件上传/预览、`/chat`、`/chat/stream`、`/chat/jobs`、会话列表/消息/删除；这些操作均在请求者自己的会话数据上，无越权）。
- `_enrich_all_user_sessions`（约 372 行）：agent 名称回填从 `filter(user_id=user_id, id__in=...)` 改为 `filter(id__in=agent_ids)`（session 本就属于请求者，无信息泄漏；同时兼容被下架智能体的历史会话显示）。
- `app/chat/chat_job.py` 约 157 行：`get_owned` → `get_accessible`。

### 6. 最近使用（`app/controllers/user_agent_recent.py`）
- `touch_recent_agent`：`get_owned` → `get_accessible`（他人使用共享智能体后可进入自己的最近使用）。
- `list_recent_agents_public`：按 `id=r.agent_id` 取智能体（不再限 `user_id=user_id`），头像 URL 改用智能体属主 username。

### 7. 知识库作用域（`app/chat/agent_service.py`，共享者检索发布者 KB）
- `_run_kb_document_preselect_with_context`（约 139 行）：`kb_scope_for(user_id, agent_id)` → `kb_scope_for(ua.user_id, agent_id)`。
- `build_model_and_agent`（约 302 行）：`kb_scope = kb_scope_for(user_id, ua.id)` → `kb_scope_for(ua.user_id, ua.id)`。
- 不变项：会话附件工具、以图检索附件校验（用聊天者自己的附件行）、会话记忆（memory scope 为 `user:agent:session`）继续按聊天者隔离，天然正确。
- KB 管理接口 `kb.py` 维持 `get_owned`，非属主不可管理发布者知识库。
- LLM 调用继续 `decrypt_api_key_safe(ua.api_key_ciphertext)`，即共享聊天用发布者 Key。

### 8. 取消发布的语义
- 非属主请求（含聊天/会话）返回 404；其历史会话保留在库中但不可继续；重新发布后恢复可用。

## 前端改造

### 1. API 封装（`web/src/api/index.js`）
- 新增 `getPublicAgentList: (params) => request.get('/user-agent/public', { params })`。

### 2. 创建/编辑表单
- `composables/agentFormCommon.js`：`emptyForm()` 增加 `is_published: false`。
- `components/AgentFormFields.vue`：加入「发布到广场」`n-switch` + 说明文案（发布后所有用户可见并可对话，模型调用费用由发布者承担）。

### 3. 智能体中心（`web/src/views/agent-hub/index.vue`）
- 加 `n-tabs`：「我的智能体」（现状：创建卡片 + 编辑/删除/知识库操作）与「智能体广场」（调 `getPublicAgentList`，卡片仅展示头像/名称/简介/发布者，点击进聊天，无编辑/删除/知识库按钮）。
- 「我的智能体」卡片可加「已发布」小标签（`n-tag`）提示发布状态。

### 4. 聊天页头部（`web/src/layout/components/header/components/AgentChatTitle.vue`）
- headerStore 已有 `creatorName` 字段；`agent-chat/index.vue` 同步头部时按 `agent.user_id === 当前登录用户 id`（userStore）传 `isOwner` 到 store，非属主隐藏「编辑」与「知识库」两个操作按钮（其余按钮保留）。

### 5. i18n（`web/i18n/messages/cn.json`、`en.json`）
- `views.agents` 下新增：`tab_mine`、`tab_public`、`label_publish`、`publish_hint`、`published_badge`、`public_empty`、`public_creator` 等中英文案。

## 验证方案
1. 双账号联调（uitest 账号 + 新注册账号，conda Kura-AI 环境启动后端 + 前端）：
   - A 发布智能体 → B 在广场可见卡片与发布者名；
   - B 进聊天：发消息流式正常、知识库检索命中 A 的 KB、会话出现在 B 侧栏最近对话、附件上传正常；
   - B 无编辑/删除/知识库按钮；直接调 update/delete/kb 接口返回 404；
   - A 设置未配置 Key 的智能体发布 → 后端拒绝；A 取消发布 → B 再发消息 404；
   - A 自己的私密智能体在广场不可见，回归编辑页试聊（`__editor_preview_`）不受影响。

## 影响与风险
- 无新增依赖、无 Postgres 表结构变更；SQLite 仅加一列（启动兜底）。
- 发布即意味着第三方可用发布者的模型额度与 KB 内容对外可检，前端文案与「发布说明」对发布者明示。
- 权限模型：仅「发布到广场全员可见」一种共享粒度（本期不做指定用户共享）。
