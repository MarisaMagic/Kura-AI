## 移除「写代码能力」(enable_code) 开关 — 实施计划

### 背景
该开关在后端仅用于向系统提示词追加一句「希望你在适当时给出可运行的代码示例」(app/chat/agent_service.py:249-251),不控制任何工具/权限。前后端全链路引用点已通过 grep 确认(共 12 处)。

### 前端修改(6 处)

1. `web/src/views/agents/components/AgentFormFields.vue`
   - 删除第 82-85 行「写代码能力」开关:`<div class="agent-enable-pair">` 内的 `.agent-enable-label` + `n-switch`(绑定 `form.enable_code`)
   - 此行剩「联网能力」「多模态视觉」两个开关,CSS 无需改动
2. `web/src/views/agents/composables/agentFormCommon.js`
   - 删除第 18 行 `enable_code: false,`(emptyForm 默认值)
3. `web/src/views/agents/edit/index.vue`
   - 删除第 137 行 `enable_code: !!d.enable_code,`(编辑回填)
4. `web/src/views/agents/composables/useAgentConfigDiff.js`
   - 第 10 行:从 `PREVIEW_CONFIG_FIELDS` 数组移除 `'enable_code'`
   - 第 65-67 行:删除 `composeSystemPromptPreview` 中的 enable_code 提示词片段
5. `web/i18n/messages/cn.json` — 删除第 57 行 `"label_enable_code": "写代码能力",`
6. `web/i18n/messages/en.json` — 删除第 57 行 `"label_enable_code": "Code tools",`

### 后端修改(3 处)

7. `app/chat/agent_service.py` — 删除 `_compose_system_prompt` 中第 249-251 行的「写代码能力说明」块
   (⚠️ 必须与第 8 步同步完成,否则运行时 `ua.enable_code` 属性访问会抛 AttributeError)
8. `app/models/user_agent.py` — 删除第 15 行 `enable_code` BooleanField
9. `app/schemas/user_agent.py` — 删除第 17 行 `enable_code: bool = False`(位于 UserAgentCommon,创建/更新模型共用)

### 明确不动的内容
- **数据库/迁移**:SQLite 的 `enable_code` 列保留。Tortoise 忽略模型未映射的孤儿列,不影响启动与查询;已存在的数据不变。不手动编写删列迁移(本地 .venv 空壳无法跑 aerich,手写迁移可能破坏迁移链)。如需彻底删列,留作后续单独处理。
- **API 路由**(`app/api/v1/user_agents/user_agents.py`):零改动。删除 schema 字段后:创建走 DB 默认 0;编辑时 payload 不再含 enable_code,`update_from_dict` 不会触碰该值(不存在「编辑后隐式重置」的问题)。
- **enable_web / supports_vision 两个开关**:保持不动(不在本次请求范围内;supports_vision 实际控制图片附件多模态能力)。

### 行为影响
- 新建/编辑智能体:不再发送 enable_code 字段。
- 已开启过该开关的存量智能体:运行时系统提示词里不再追加「给出可运行代码示例」的提示(即该开关唯一效果的移除,符合预期)。
- 聊天管线无其他依赖此字段的逻辑,模型工具注册不受影响。

### 验证
- 后端:`python -m py_compile` 对改动的 3 个 Python 文件做语法级校验(按环境限制,无法启动服务做契约级验证)
- 全链路:`grep -rn -i "enable_code\|label_enable_code"` 确认零残留(迁移文件中的历史 SQL 除外)
